## What was done

### 1. The two defects carried from 017

#### 1a. The winner's-verdict-asserted-of-every-engine class

**The 017f property test covered `compare_engines` and nothing else**, and the
brief's question was whether the rest of the report had the same shape. It did,
in three more places. All three are one shape: a sentence or a cell built from
ONE verdict and presented as if it covered the set.

| # | site | what it rendered on the 017e shape (qdrant meets, pgvector fails) |
|---|---|---|
| 1 | `html._options_table` | `o.verdict_for(name)` — the **first** verdict. A flat green `meets` cell under `latency_p95`, with pgvector's 317.41 ms **nowhere on the page** |
| 2 | `html._recommendation` | `latency_p95` twice, one green dot and one red, **neither naming an engine** — one constraint answered twice and contradictorily |
| 3 | `report.decision_log` `meets` entry | `… meets every constraint that could be checked: latency_p95 7.72 ms <= 40 ms; qps 200.00 >= 200.` with the failures two entries above under `fails` |

Number 3 is the one worth naming, because the code already said it must not
happen. `collapse_by_constraint` folds per-engine verdicts permissively — a
constraint `meets` when at least one engine meets it — and its docstring
states the precondition:

> The permissive direction is deliberate and it is only safe **because the
> decision log names the engine every time**: "meets on qdrant" is a fact,
> "meets" alone would not be.

The `fails` entries named the engine. The `meets` entry did not.

**Fixed:**

- `Option.verdict_for` is **gone**, replaced by `verdicts_for(name)` returning
  every verdict. Two of the three defects came from that one accessor.
- `html._verdict_cell` renders the **collapsed** outcome as the cell's own
  colour — the same rule that decides `Option.outcome`, so the row cannot
  contradict its own overall column — with each engine's verdict beneath it
  and every reason and source in the `title`.
- `html._recommendation` appends the engine to each constraint row.
- `report._not_on_every_engine` adds the clause the `meets` line was missing:

      … meets every constraint that could be checked: recall_at_10 0.9990 >=
      0.9500; latency_p95 on qdrant 7.72 ms <= 40 ms; qps on qdrant 200.00 >=
      200. This is not true of every engine measured: latency_p95 does not on
      pgvector (fails); qps does not on pgvector (fails). `meets` for a
      configuration means it meets on at least one engine measured, not on all
      of them

**And the property test now covers every generated surface, derived rather
than declared.** `oneground/report/test_no_lent_outcomes.py` (13 tests) walks
the decision log, `compare_engines`, `runner_up_lines` and the rendered HTML
**section by section**, over every combination of per-engine outcomes, and
asserts: a uniformity claim may only be made about a constraint whose engines
are uniform; a uniformity claim that names no constraint is itself a defect;
and a constraint whose engines disagree must name both wherever it appears.

Two AST guards keep the coverage honest rather than hoping it stays current:
one extracts every `add("<kind>", …)` literal from `decision_log` and
`_declared_log` and fails if a kind is not covered here; the other extracts
every function `render_html` splices into the page and requires the same. A
new log entry or a new HTML section cannot be added without a decision about
this file. The third guard is an AST walk over the shipped tree for any
`verdict_for` attribute — the accessor that produced two of the three.

## Observed, not done

- **`verify --up` races pgvector's first boot on a cold volume.** Calibrating
  pgvector failed with `server closed the connection unexpectedly`, and the
  container's log shows why: on a fresh named volume the official image starts
  Postgres once to run `initdb`, shuts it down, and starts it again. `verify`
  connected inside that window. The fix is the shape 017c already established
  one layer up — the readiness probe there asks a question the engine cannot
  answer unless it is serving, and the *bring-up* does not. Worked round here
  by composing the container first and pointing `ONEGROUND_PGVECTOR_URL` at it;
  not fixed, because the brief names no file in `verify/`.
- **`environment.PINNED` does not include psycopg or qdrant-client.** That is
  defensible — a client version does not move a recall number the way numpy
  does — but it means `test_packaging.py`'s "a bare install yields the pinned
  environment" check says nothing about the two engine clients. An adapter
  pinned wrong would be caught by the conformance suite against a live engine
  and by nothing else.
- **`calibrate engine` re-runs the whole verify.** `run_engine` calls
  `V.run(...)`, so calibrating a workdir that already holds a `verify.json`
  re-ingests, re-searches and re-runs every load phase. On `arxiv-150k` that
  is a full local verify of 150,000 vectors, which is why this task calibrated
  on `arxiv-smoke` instead. A `--from-workdir` that read the existing
  `calibration_error_recall` — which `verify` already computes and writes —
  would make the history cheap to keep current. Not in this brief.
- **The calibration footer does not say when a citation predates the run it
  foots.** Task 017 added exactly that check for the price table (`as_of`
  against `verify_info.run_at`, reported not raised). The engine citation has
  the same shape and no such check: before this task it cited a 2026-09-11
  calibration under a report whose measurements were taken on 2026-09-13, and
  nothing said so. The right answer is probably not a date comparison but a
  `pins_sha256` comparison — a calibration under the same pins is still
  current however old it is — and that is a design decision, not a fix.
- **`fixture verify` on 150,000 vectors is memory-bound on this machine**, as
  task 016 already recorded for `stackexchange-150k`'s two semantic-sharded
  rows. This run paged heavily throughout (see Measurements). The numbers are
  right; the wall clock is a property of a 7.6 GB laptop and the docs' "about
  ten minutes" is measured on a machine with headroom.
- **The `docs/EXTERNAL_RUN.md` instruction is still written around one
  fixture.** A section for the second was added rather than the paragraph
  rewritten, because the paragraph is deliberately one block meant to be
  forwarded as-is and splitting it in two would cost more than it buys.
- **`site/teaser/` still renders arXiv only.** Its data, its ground view and
  its verdict panel are all `arxiv-150k`. The second fixture is named nowhere
  on the page. That is a content decision about the public site, and the brief
  names only "the site copy that names a version".
